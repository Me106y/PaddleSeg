总体结论

两类实验 = 一条「语义分割 + PP-HumanSeg14K」的线

对比实验是 6 个轻量分割模型在同一数据集与协议下的横向比较（论文 TABLE III）；消融实验是在 RepViT 骨干上逐步加 GAM / ASPP / PPM / MSF 的纵向拆分（论文 TABLE VI）。两者在代码上落在同一条链：configs/ 选模型与超参 → paddleseg/models/ 定义模型与骨干 → paddleseg/datasets/pp_humanseg14k.py 读数据 → tools/train.py · val.py · predict.py 跑训练与评测。

因此「去膨胀」有明确边界：仓库里约 95% 的目录（contrib/、EISeg/、Matting/、deploy/、test_tipc/ 等）与这两类实验零依赖，可整目录移除；paddleseg/ 内部则按「这条线要不要 import」逐个裁剪。

[EVAL] #Images: 2431 mIoU: 0.8893 Acc: 0.9537 Kappa: 0.8814 Dice: 0.9407 PSNR: 20.6647 SSIM: 0.9321
[EVAL] TemporalConsistency: 0.9686 (Flicker: 0.0314, ChangedPixelRatio: 0.0649, ConsecutivePairs: 2430)

口径：三项指标都算在二值化前景掩膜（pred > 0 对 label > 0）上——这正是下游恢复管线真正消费的东西。PSNR 对完全一致的掩膜封顶 100 dB。TemporalConsistency = 1 − Flicker，其中 Flicker 是「相邻帧之间 GT 未变化像素上的预测平均绝对变化量」；ChangedPixelRatio 给出这些帧对里 GT 实际变化的像素比例作为参照。时序一致性只在验证列表按视频帧顺序排列时才有意义——PaddleSeg 以 shuffle=False, drop_last=False 求值，因此数据集顺序即 val.txt 顺序，满足前提。多标签模式下会自动跳过这三项。

7.3 恢复质量评估（视频侧）

上一节是端上「恢复输出 ↔ 参考帧」的即时比较；批量出表用脚本：dashboard-ios/scripts/eval_restoration_video.py。它把一张无遮挡的干净参考图与处理后的视频逐帧比对，输出 PSNR / SSIM / MAE 与帧间稳定性。

# 最简：干净参考图 + 处理后的视频
python eval_restoration_video.py --reference ref.png --restored restored.mp4

# 再给原始（未处理）视频：自动推导逐帧遮挡区域，额外输出「仅遮挡区」口径
python eval_restoration_video.py --reference ref.png --restored restored.mp4 --input raw.mp4
输出含义
psnr_full / ssim_full / mae_full全帧（或 --roi）口径
psnr_occ / ssim_occ / mae_occ / occ_ratio仅遮挡区口径——只有这块是恢复算法真正产出的
mad_prev_full与上一帧的平均绝对差（相机固定，即闪烁量级）
flicker_matched只在「本来就已恢复正确」的像素上统计的帧间抖动——这才是闪烁
CSV + 汇总逐帧明细落盘，控制台给 mean / median / p5 / p95
口径提醒

两个必须处理的前提

① 只在遮挡区上算。未遮挡像素在恢复输出里本来就是照抄，占比常在 90% 以上，只报全帧会被这批「白送」的像素抬高到没有区分度——所以脚本同时给全帧与仅遮挡区两个口径。
② 参考只在「内容未变」的窗口内有效。一旦画面被写过或擦过，开场前那张干净参考就过期了，此时指标下降是内容变了而不是算法错。建议把评估限制在内容未变的片段，或分段各自取参考。

口径与 iOS 侧 RestorationMetrics.swift 完全一致（亮度通道、11×11 高斯窗 σ=1.5、C1/C2 标准常数、data_range=255），三处（PaddleSeg / iOS / 视频脚本）的 SSIM 可以直接放在同一张表里。已用合成数据自测：参考图 + 60 帧恢复视频 + 带遮挡的原始视频，注入「恢复残留」窗口后 PSNR 全帧由 42.9 掉到 37.4、窗口结束回到 43.0，遮挡区占比 13.6% —— 定位与量级都符合预期。

仓库根目录新增 Dockerfile 与 .dockerignore。服务器上只要装了 NVIDIA 驱动 + nvidia-container-toolkit，一条命令就能构建出带全部依赖与本仓库代码的镜像。

  -v "$PWD/output:/workspace/output" \
  -v "$PWD/log:/workspace/log" \

    --save_dir output/repvit_v8_20 --do_eval --use_vdl --save_interval 500
关键点

镜像里必须固定 PYTHONPATH=/workspace

本仓库 tools/*.py 依赖「仓库根在 sys.path 上」。若不固定，python tools/val.py 会把 tools/ 当作 sys.path[0]，从而 import 到 site-packages 里的上游 paddleseg，报 XXX was not found。Dockerfile 里用 ENV PYTHONPATH=/workspace 解决，并在构建阶段加了一条断言：import 到非 /workspace 的 paddleseg 就让 build 失败。

未验证项：本机没有 docker CLI，Dockerfile 未经实际 build；基础镜像标签 paddlepaddle/paddle:3.0.0-gpu-cuda12.6-cudnn9.5 是按本地 paddle 3.0.0 推断的，未联网核对。若拉不到，按文件注释里的命名规则换标签并用 --build-arg BASE_IMAGE=... 覆盖。另：--shm-size 别省，PyTorch/Paddle 的 DataLoader 共享内存不足会直接崩。
